# SkillSmith 9 分 30 秒路演脚本

## 核心主张

Skill 能过安全扫描，不代表它让 Agent 变好。SkillSmith 在 DGX Spark 本地，用**同一模型、公平对照、真值评分、真实 Agent 触发**来决定一个 Skill 能不能进工作流——现场演示同一道门禁**拦下一个、放行一个**。

> 呼应 NVIDIA Verified Skills：“一个 skill 可以通过所有安全检查，但仍然让 Agent 表现更差——Tier 3 就是让这无所遁形。”企业内部的 Skill 进不了官方目录，但同样需要这条信任链，而且数据不能出本机。

## 时间线

### 0:00-0:50 问题

- 团队把一次成功的提示词包成 Skill，就以为拥有了能力。
- 但没人能回答：它真的比不装更好吗？Agent 会在该用时用、不该用时不用吗？
- 常见的“提升”是假的：基线不知道输出格式，当然输给 Skill。我们自己第一版就踩了这个坑（旧数据 23.6%→100%，已作废并保留记录）。

### 0:50-1:40 公平评测的三条规则

1. **同一台 DGX、同一 Qwen3.6、同一图片与请求**；基线也拿到同样的输出格式。
2. **按真值打分**：测试图由脚本拼合生成，每个排面都是已知的。
3. **触发用真实 Agent 测**：OpenClaw 在 20 多个 Skill 中自己决定加载谁，从它的会话记录判定；每条提示重复多次。

若 Skill 附带业务资料，再加一组 **“直接粘贴资料”**：Skill 必须胜过“把同样资料贴进提示词”，否则不算它的功劳。

### 1:40-3:40 被拦下：零售货架巡检（`retail-shelf-audit`）

展示 `evidence/dgx-2026-09-23/BENCHMARK.openclaw.md`：

- 安全扫描 PASS；OpenClaw 真实触发 36/36 正确。
- 但任务得分 **82.7%（不装）vs 82.3%（装）**——Qwen3.6 本来就会数排面。
- 门禁判定 **BLOCKED，不安装**。一句话：“它安全、好找，但没用。”

### 3:40-6:40 被放行：门店陈列合规（`planogram-compliance`）

Skill 附带门店 A12 的陈列图、SKU 编码表和门店政策（低于最低排面才算 LOW；达到最低线即 OK；未排期的 SKU 为 MISPLACED）。

展示 `evidence/dgx-2026-09-24/planogram-compliance/generated/BENCHMARK.md`（6 张场景图）：

| | 不装 | 粘贴资料 | 装 Skill |
| --- | ---: | ---: | ---: |
| 任务得分 | 11.1% | 72.6% | **81.4%** |
| 状态判定准确率 | 0% | 77.4% | **90.5%** |
| 平均延迟 / 输出 token | 18.6 s / 558 | 24.6 s / 748 | **18.5 s / 544** |

讲清楚差值来源：粘贴资料的模型会把“低于目标”一律标成 LOW（在合规图上误报 4 条），Skill 的政策规则消除了这类误报；同时更快、更省 token。

OpenClaw 真实触发 35/36：唯一一次漏触发是英文提示被邻近的 `retail-shelf-audit` 抢走——两个 Skill 共存时的真实边界问题，照实展示。

门禁 **PASS → 自动安装**。

### 6:40-8:10 换新输入复现

在从未参与评测的新照片 `scenes/replay-a12-evening.png` 上运行已安装的 Skill，并用同一评分器对真值打分：

- 3 个真实偏差（可乐 LOW、水 LOW、薯片 OOS）全部找出；
- 1 条误报（绿茶 5 个排面、最低线 4，被标成 LOW）；任务得分 88.6%。

主动说出这条误报：评测不是为了好看，而是让团队知道还剩什么问题。

### 8:10-9:30 收束

- 生成：把一次成功沉淀成带资料、带护栏的 Skill。
- 安全：扫描不过不评测。
- 评测：同模型、真值、粘贴资料对照——拦下没用的，放行有用的。
- 触发：真实 Agent 里多次运行，而不是关键词估算。

结束句：**SkillSmith 不是让 Agent 多做一次，而是让组织只留下真正有用的能力。**

## 现场执行

```bash
./scripts/demo-dgx.sh     # 彩排实测 580 秒：零售 BLOCKED → 陈列合规 PASS 并安装 → 新照片复现并打分
```

OpenClaw 触发评测每次约 70 秒/提示，不在现场实时跑，展示已存档的结果与会话记录。

## 现场失败预案

- 模型端点未就绪：展示 `evidence/` 中已存档的 CAPTURE.json、原始回答和 BENCHMARK，并说明时间与模型；不要把 fixture 结果当实测。
- 实时数字与存档不同：采样温度为 0，但仍可能有小幅波动（彩排中零售 Skill 为 82.7% vs 82.7% 持平，仍被拦截——门禁要求严格优于基线）；以现场结果为准并如实说明。
- 推理超时：保留已完成阶段的日志，不重复点击造成并发请求。
- 现场网络不可用：使用节点预置 vLLM 镜像和本地模型；正式演示不依赖外网。
