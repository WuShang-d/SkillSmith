# SkillSmith 9 分 30 秒路演脚本

## 核心主张

别人让 Agent 完成一次任务；SkillSmith 把这次成功锻造成可复用、可评测、可审计的能力资产。

## 时间线

### 0:00-0:45 问题

- 模型会做，不等于团队拥有这项能力。
- 长提示词无法稳定触发，无法复现，也无法交给安全团队审查。
- SkillSmith 的目标是在 10 分钟内把成功工作流变成正式 Skill。

### 0:45-1:30 架构

展示五段流水线：生成 → 安全检查 → A/B 评测 → 安装 → 换输入复现。

强调三条边界：业务图片留在 DGX；凭据只从环境变量读取；任一门禁失败就停止安装。

### 1:30-3:00 输入成功工作流

打开网页，展示货架巡检示例：

- 正触发：巡检图片、统计排面、识别空位。
- 负触发：营销文案、无图片的数据库补货、人脸身份识别。
- 输出契约：`image_quality`、`sku_facings`、`empty_gaps`、`uncertainties`。
- 护栏：只报告像素证据，不推断顾客属性或画外库存。

选择新图片。端点固定为 DGX 本机回环地址。

### 3:00-4:20 生成与安全门禁

点击“开始锻造 Skill”。展示生成目录：

```text
retail-shelf-audit/
├── SKILL.md
├── scripts/run.py
├── references/workflow.json
├── evals/evals.json
├── SECURITY_REPORT.json
└── BENCHMARK.md
```

指出 SkillSmith 不声称自己完成了 NVIDIA 官方签名；本地扫描是进入正式发布管道前的预检。

### 4:20-6:20 同模型 A/B

说明公平条件：同一台 DGX、同一模型、同一图片、同一用户请求；唯一变量是是否加载 Skill。

展示：

- 原始回答分别保存在 `<case>.baseline.txt` 和 `<case>.skill.txt`。
- `CAPTURE.json` 记录模型名和两次延迟。
- 两组都拿到相同的输出格式，差值只来自 Skill 的流程与护栏；按人工标注的真值评分。
- 触发率来自真实 OpenClaw Agent（36 次运行），不是关键词匹配。
- Fixture 数字只能称作流水线自测；路演必须展示 live capture 数字。

**待定（2026-09-23 实测）**：零售示例在公平 A/B 下没有提升（任务得分
82.7% → 82.3%），门禁拦截了安装；OpenClaw 触发 36/36 正确。旧的
“23.6% → 100%”已作废（基线当时不知道输出格式），不得再引用。
在换上能通过门禁的 Skill 之前，本段演示需要重写。

### 6:20-7:20 安装

只有安全和评测均通过，Skill 才复制到 Agent workspace。故意指出失败路径：高危发现或评测未提升时，状态为 `BLOCKED`，不会安装。

### 7:20-8:40 换新输入复现

开启新会话或使用第二张货架图片。只说自然语言请求，不粘贴原始长提示词。展示 Skill 自动触发并返回同一 JSON 契约。

实测 runner 会在落盘前校验四个精确顶层字段；字段缺失或 JSON 非法时
明确失败，不会把近义字段当作成功。

### 8:40-9:30 收束

- 生成：把隐性经验结构化。
- 安全：把风险挡在安装前。
- 评测：用同模型 A/B 证明贡献。
- 复现：换会话、换输入仍能工作。

结束句：**SkillSmith 不是让 Agent 多做一次，而是让组织从此拥有这项能力。**

最后亮出实测总时间：模型预热后生成 → 扫描 → A/B → 60 次触发评测共 **182 秒**。

## 现场失败预案

- 模型端点未就绪：不要把 fixture 分数冒充实测；展示最近一次真实 `CAPTURE.json` 和原始回答，并明确时间与模型。
- 页面异常：运行 `scripts/demo-dgx.sh`，所有阶段使用同一后端。
- 推理超时：保留已完成阶段的日志，不重复点击造成并发请求。
- 新输入质量差：把“不确定”作为正确输出，而不是临时换图掩盖问题。
- 现场网络不可用：使用节点预置 vLLM 镜像和本地模型；正式演示不依赖外网。
