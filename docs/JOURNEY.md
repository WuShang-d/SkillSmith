# 我们的门禁，先拦下了我们自己

**SkillSmith 参赛历程 · 第三届 NVIDIA DGX Spark Hackathon**

## 起点：一次成功，算不算能力？

9 月 20 日训练营那天，NVIDIA 的老师讲 Verified Skills：一个 Skill 要经过扫描、评测、签名、说明卡，才进官方目录。其中有一句让我们停了下来——

> 一个 skill 可以通过所有安全检查，但仍然让 Agent 表现更差。

我们想到的是企业里更常见的情况：某个同事用 Agent 跑通了一次任务，大家就把提示词打包成 Skill，推给所有人。这些自研 Skill 进不了官方目录，却同样需要回答"它到底有没有用"。于是我们决定做 SkillSmith：把一次成功的多模态工作流生成 Skill，再用一道发布门禁决定它能不能上线。

## 9 月 20 日：跑通了，数字也很好看

当天我们把整条流水线搭了起来：工作流规范校验、生成 `SKILL.md` 和 runner、安全规则扫描、A/B 评测、条件安装、换输入复现。核心不依赖任何第三方 Python 库，方便直接搬到 DGX Spark 上。

在 DGX Spark 上，我们用 vLLM 把预装的 Qwen3.6-35B-A3B 跑在回环地址上。GB10 是 ARM64 加统一内存，需要关掉 DeepGEMM、改用 Triton MoE 后端；我们把这些参数固化进启动脚本，保证谁来都能一键复现。

真实复现时还踩了一个坑：模型偶尔会返回意思相近、但名字不对的字段。我们给生成的 runner 加了严格的输出契约——字段缺失或 JSON 非法就明确失败，并补了回归测试。

当晚第一份真实结果出来：**不装 Skill 23.6%，装上 100%**。我们很兴奋。

## 9 月 23 日：我们把自己的数字作废了

冷静下来复盘，问题很明显：基线根本不知道要输出什么格式，而评分器只检查字段名。100% 衡量的是"知不知道字段名"，不是 Skill 有没有让模型看得更准。

我们做了三件事：

1. **对照组也拿到相同的输出格式**，只有 Skill 组多了流程和护栏；
2. **按真值打分**，逐层核对排面数、空位和遮挡；
3. **用真实 Agent 测触发**：每条正负提示在 OpenClaw 里作为新会话跑 3 次，看它自己的会话记录有没有加载这个 Skill，而不是用关键词重合来估算。

重跑之后，零售货架巡检 Skill 是 **82.7% 对 82.3%**——Qwen3.6 本来就会数排面，装了没有更好。安全扫描通过，OpenClaw 触发 36 次全对，可我们自己的门禁判了 **BLOCKED，不安装**。

那一刻有点尴尬：精心做的 Skill 被自己的工具拦下了。但我们也意识到，这正是 SkillSmith 该做的事。旧数据没有删，标明作废后留在仓库里。

## 9 月 24 日：什么样的 Skill 才有用？

如果模型本来就会，Skill 就没有价值。Skill 真正能带来的，是模型不知道的东西：**这家店的陈列图、SKU 编码表、门店政策**。

于是我们做了第二个 Skill：门店陈列合规。为了拿到精确真值，我们用脚本把商品一个个拼进货架场景，每个排面都已知。我们还加了第三个对照组——**把同样的资料直接粘贴进提示词**。如果 Skill 赢不过粘贴，提升就不该算它的功劳。

结果：不装 11.1%，粘贴资料 72.6%，装 Skill 78.4%，而且比粘贴快约 5 秒。差距来自门店政策：粘贴资料的模型会把"低于目标"一律标成 LOW，Skill 知道"达到最低排面就是 OK"。门禁放行。

在一张从没参与评测的傍晚照片上，它找出了全部 3 个真实偏差，也报了 1 条误报。我们把误报写进了结果——评测不是为了好看，而是让团队知道还剩什么问题。

## 同一天：NVIDIA 的扫描器也拦下了我们

接着我们把 NVIDIA SkillSpector 接进门禁，第一个扫的就是自己生成的 Skill。结果是 **风险分 100，DO_NOT_INSTALL**：runner 会把 `OPENAI_API_KEY` 发到网络，Skill 里残留编译好的 `.pyc`，也没有声明工具权限。

这些都是真问题。修复后 runner 只连 127.0.0.1、不读环境变量、声明权限，重扫风险分降到 3。加固改动了 `SKILL.md`，陈列合规的分数从 81.4% 变成 78.4%，我们以发布版为准如实更新。

最后补上签名：用本地根证书按 OpenSSF Model Signing 签发，安装前后都验签。改一个文件、加一个文件、用别人的证书重签，三种篡改都会被拒绝。整条演示在 DGX 上跑完一遍约 9.5 分钟。

## 最后几天：技术做完了，还要讲清楚

看到其他队的作品都从一个具体的人和场景讲起，我们发现自己一直在讲流水线和百分比，却没讲一个人为什么需要它。

所以我们换了讲法：从一个虚构的便利店运营小周讲起。他让 Agent 查了一次货架，一次就查对了，老板说下周推到全部门店。可一次做对是运气——推之前，谁来回答"装上真的更好吗"？

## 我们学到的

- **先怀疑自己最好看的数字。** 23.6% → 100% 是我们离错误结论最近的一次。
- **门禁要对自己生效。** 被自己的门禁和 NVIDIA 的扫描器各拦一次，是这个项目最有说服力的证据。
- **Skill 的价值在模型不知道的东西里。** 流程和格式模型大多会，组织自己的知识和规则才是 Skill 该装的。
- **好的工程也需要一个好故事。**

一次做对是运气，每次都对才是能力。SkillSmith 想做的，就是把 Agent 的一次成功，锻造成全公司都敢装的能力。
